# วิธีส่งรายชื่อลูกค้าให้อีกเครื่องโดยไม่ใช้ GitHub

1. เครื่องต้นทาง: ตั้งค่า → ดาวน์โหลดไฟล์สำรองเพื่อย้ายเครื่อง (.db)
2. ส่งไฟล์ที่ดาวน์โหลดให้อีกเครื่องผ่าน USB หรือช่องทางส่งไฟล์ที่ใช้ภายในร้าน
3. เครื่องปลายทาง: ตั้งค่า → นำรายชื่อลูกค้าจากไฟล์สำรอง → เลือกไฟล์ .db → อ่านคำเตือนและยืนยัน
4. ระบบสำรองรายชื่อเดิมก่อนแทนที่ แล้วโหลดหน้าจอใหม่ รายชื่อลูกค้าและดาวที่ปักหมุดมาจากไฟล์ ผู้ส่ง การตั้งค่า และประวัติพิมพ์ของเครื่องปลายทางไม่เปลี่ยน

การวางไฟล์ลงใน backups อย่างเดียวไม่กู้คืนข้อมูล ต้องกดนำเข้าผ่านแอป รองรับ .db ขนาดไม่เกิน 10 MB สำหรับ .sql.gz ให้ใช้ขั้นตอนกู้คืนเต็มระบบของผู้ดูแลด้านล่าง ห้ามเปลี่ยนนามสกุลไฟล์เพื่อฝืนนำเข้า ไม่มีงานรอหรือกำลังพิมพ์ก่อนนำเข้า
# ย้ายเครื่องโดยใช้ข้อมูลเดิม

ช่อง Git repo ในแอปเป็นปลายทางส่งสำรอง ไม่ดาวน์โหลดและไม่ซิงก์ข้อมูลกลับอัตโนมัติ มีปุ่มดาวน์โหลดสำรองล่าสุดจาก GitHub ผ่าน SSH และมีปุ่มนำเข้ารายชื่อลูกค้าจากไฟล์ .db (การกู้คืนเต็มฐานข้อมูลยังใช้ขั้นตอนด้านล่าง) (ปุ่มนำเข้า Excel ใช้กับรายชื่อลูกค้าเท่านั้น)

1. เครื่องเดิม: ตั้งค่า → สำรองข้อมูลตอนนี้ รอจนสถานะแสดงผลสำรองรอบใหม่ หากส่ง Git ไม่สำเร็จยังมีไฟล์ใน backups บนเครื่องเดิม
2. เลือกไฟล์ .sql.gz หรือ .db รอบล่าสุดจากโฟลเดอร์ backups หรือดาวน์โหลด .sql.gz จาก repository สำรองบน GitHub ด้วยบัญชีที่มีสิทธิ์เข้าถึง แล้วคัดลอกไปเครื่องใหม่
3. เครื่องใหม่: ติดตั้งตามคู่มือ เปิดระบบครั้งแรกเพื่อเตรียมโปรแกรม จากนั้นกดปิดระบบในตั้งค่า หรือเปิด stop-label-pro-max-local.vbs (ปิด browser อย่างเดียวไม่พอ)
4. ให้ผู้ดูแลเปิด Terminal ในโฟลเดอร์โปรเจคแล้วรัน npm run restore -- "C:\Transfer\ชื่อไฟล์.sql.gz" โดยเปลี่ยนเป็นพาธไฟล์จริง รองรับ .db ด้วย ถ้าใช้ portable Node ให้ใช้ .runtime\node-v24.x.x-win-x64\node.exe scripts\restore.mjs "C:\Transfer\ชื่อไฟล์.sql.gz" (ตรวจตำแหน่ง Node ใน .runtime ก่อน)
5. เปิดทางลัด Label Pro Max Local ตรวจรายชื่อลูกค้า ดาวที่ปักหมุด ผู้ส่ง และประวัติ ข้อมูลกู้คืนแทนชุดเดิม ไม่รวมสองชุดเข้าด้วยกัน ระบบสำรองข้อมูลของเครื่องปลายทางก่อนแทนที่
6. ตั้งชื่อสาขา ชื่อเครื่องพิมพ์ และ repository สำรองให้ตรงกับเครื่องใหม่ ก่อนลองพิมพ์หนึ่งใบ ประวัติงานที่รอพิมพ์ในไฟล์สำรองอาจกลับมาทำงาน จึงควรย้ายเมื่อเครื่องเดิมไม่มีงานรอ/กำลังพิมพ์

หากย้ายแทนเครื่องเดิม ใช้ repository สำรองเดิมได้ หากสองเครื่องทำงานแยกกันให้ใช้คนละ repository เพื่อหลีกเลี่ยงประวัติสำรองชนกัน ไม่ควรเปิดเครื่องเดิมส่งสำรองพร้อมเครื่องใหม่ใน repository เดียวกัน

การดาวน์โหลดทำได้จาก ตั้งค่า → ดาวน์โหลดสำรองล่าสุดจาก GitHub โดยบันทึก URL repository สำรองก่อน และตั้ง SSH key ให้มีสิทธิ์อ่าน repository นี้บนเครื่องนั้น พร้อมยืนยัน host github.com ครั้งแรกโดยผู้ดูแล ปุ่มดาวน์โหลดไม่กู้คืนข้อมูลทันที ผู้ดูแลควรช่วยขั้นตอนกู้คืน พนักงานดาวน์โหลด .db และนำเข้ารายชื่อลูกค้าได้ในแอป การกู้คืนผู้ส่ง การตั้งค่า และประวัติทั้งหมดจาก .db/.sql.gz ใช้ขั้นตอนผู้ดูแล

## ทดสอบหลายโฟลเดอร์ในเครื่องเดียวกัน

localhost:3000 ชี้ระบบที่กำลังเปิดอยู่เพียงชุดเดียว ไม่เปลี่ยนตามโฟลเดอร์ที่เพิ่ง clone ทางลัด Desktop เดิมยังชี้โฟลเดอร์เดิม ตรวจโฟลเดอร์ระบบและฐานข้อมูลในหน้าตั้งค่า ก่อนแก้ข้อมูล หากต้องการทดสอบสำเนาใหม่ ให้ปิดระบบชุดเดิมผ่านปุ่มปิดระบบ แล้วเปิด start-label-pro-max-local.vbs จากภายในโฟลเดอร์สำเนาใหม่โดยตรง เมื่อเปิดสำเร็จ launcher จะปรับทางลัดไปยังสำเนาใหม่ด้วย หากต้องการกลับชุดเดิมให้ปิดชุดทดสอบแล้วเปิดตัวเปิดจากโฟลเดอร์เดิม data/ และ backups/ ไม่อยู่ใน Git เพราะเป็นข้อมูลเฉพาะเครื่อง data/ สร้างเมื่อเริ่มระบบ และ backups/ สร้างเมื่อสำรองครั้งแรก

SSH deploy key ที่มีสิทธิ์เฉพาะ repository โค้ด อ่าน repository สำรองไม่ได้ ต้องใช้ key แยกสำหรับสำรอง หรือ key บัญชีที่ได้รับสิทธิ์อ่าน repository สำรอง ห้ามแจก private key ลง Git หรือฝังในหน้าเว็บ
