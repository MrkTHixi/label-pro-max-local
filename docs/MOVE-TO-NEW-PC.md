# ย้ายเครื่องโดยใช้ข้อมูลเดิม

ช่อง Git repo ในแอปเป็นปลายทางส่งสำรอง ไม่ดาวน์โหลดและไม่ซิงก์ข้อมูลกลับอัตโนมัติ ขณะนี้ไม่มีปุ่มอัปโหลดไฟล์สำรองเพื่อกู้คืนในแอป (ปุ่มนำเข้า Excel ใช้กับรายชื่อลูกค้าเท่านั้น)

1. เครื่องเดิม: ตั้งค่า → สำรองข้อมูลตอนนี้ รอจนสถานะแสดงผลสำรองรอบใหม่ หากส่ง Git ไม่สำเร็จยังมีไฟล์ใน backups บนเครื่องเดิม
2. เลือกไฟล์ .sql.gz หรือ .db รอบล่าสุดจากโฟลเดอร์ backups หรือดาวน์โหลด .sql.gz จาก repository สำรองบน GitHub ด้วยบัญชีที่มีสิทธิ์เข้าถึง แล้วคัดลอกไปเครื่องใหม่
3. เครื่องใหม่: ติดตั้งตามคู่มือ เปิดระบบครั้งแรกเพื่อเตรียมโปรแกรม จากนั้นกดปิดระบบในตั้งค่า หรือเปิด stop-label-pro-max-local.vbs (ปิด browser อย่างเดียวไม่พอ)
4. ให้ผู้ดูแลเปิด Terminal ในโฟลเดอร์โปรเจคแล้วรัน npm run restore -- "C:\Transfer\ชื่อไฟล์.sql.gz" โดยเปลี่ยนเป็นพาธไฟล์จริง รองรับ .db ด้วย ถ้าใช้ portable Node ให้ใช้ .runtime\node-v24.x.x-win-x64\node.exe scripts\restore.mjs "C:\Transfer\ชื่อไฟล์.sql.gz" (ตรวจตำแหน่ง Node ใน .runtime ก่อน)
5. เปิดทางลัด Label Pro Max Local ตรวจรายชื่อลูกค้า ดาวที่ปักหมุด ผู้ส่ง และประวัติ ข้อมูลกู้คืนแทนชุดเดิม ไม่รวมสองชุดเข้าด้วยกัน ระบบสำรองข้อมูลของเครื่องปลายทางก่อนแทนที่
6. ตั้งชื่อสาขา ชื่อเครื่องพิมพ์ และ repository สำรองให้ตรงกับเครื่องใหม่ ก่อนลองพิมพ์หนึ่งใบ ประวัติงานที่รอพิมพ์ในไฟล์สำรองอาจกลับมาทำงาน จึงควรย้ายเมื่อเครื่องเดิมไม่มีงานรอ/กำลังพิมพ์

หากย้ายแทนเครื่องเดิม ใช้ repository สำรองเดิมได้ หากสองเครื่องทำงานแยกกันให้ใช้คนละ repository เพื่อหลีกเลี่ยงประวัติสำรองชนกัน ไม่ควรเปิดเครื่องเดิมส่งสำรองพร้อมเครื่องใหม่ใน repository เดียวกัน

การดาวน์โหลดจาก GitHub ทำได้ผ่าน browser; ยังไม่มีปุ่มดึง backup จาก GitHub ในแอป ผู้ดูแลควรช่วยขั้นตอนกู้คืน พนักงานกดสำรองในแอปได้ แต่ยังไม่สามารถอัปโหลดไฟล์ .db/.sql.gz เพื่อกู้คืนผ่านหน้าแอปได้
