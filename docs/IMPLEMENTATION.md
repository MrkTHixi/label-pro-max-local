# ผลปรับปรุง LabelPro Local 0.2.0

วันที่: 6 ตุลาคม 2026 (Asia/Bangkok)

## สิ่งที่เปลี่ยน

- เปิดจาก start-labelpro.vbs ตัวเดียว เตรียม Node.js แบบ portable เมื่อเครื่องยังไม่มี เตรียม dependency และ Chromium แล้วเริ่ม server/worker แบบซ่อนหน้าต่าง รอความพร้อมก่อนเปิดเว็บ
- เปิดซ้ำใช้ชุดเดิม มีตัวล็อกแยกตามฐานข้อมูล และมีปุ่มเริ่มใหม่/ปิดระบบกับ stop-labelpro.vbs
- ฉลากใช้ HTML/CSS และ Chromium จัดอักษรไทย เก็บ Noto Sans Thai พร้อม OFL ในโปรเจค ตัวอย่างหน้าเว็บใช้เทมเพลตเดียวกับ PDF
- ปรับขนาด MediaBox ของ PDF ให้เป็น 100 × 150 มม. โดยตรง ตรวจว่ามีหน้าเดียว และแจ้งเมื่อข้อความยาวเกินพื้นที่
- Worker ใช้ snapshot ผู้ส่ง/ผู้รับตอนสั่ง พิมพ์ทีละงาน ป้องกันเปิด worker ซ้อน และไม่ส่งงานที่ผลไม่แน่นอนซ้ำเองหลังหยุดผิดปกติ
- PDF ใช้ไฟล์ชั่วคราวเฉพาะระหว่างส่งพิมพ์ ล้างทั้งสำเร็จและล้มเหลว; mock ไม่สร้าง TXT ต่อทุกงาน; ไฟล์ temp เก่ากว่า 24 ชั่วโมงล้างตอนเริ่ม worker
- ดาวน์โหลด PDF เฉพาะงานจากหน้าคิวได้ ชุดไฟล์เดิมใน printed/ ยังอยู่
- เพิ่มปุ่มล้างลูกค้าทั้งหมด แสดงจำนวนรวมรายการที่ปิดใช้งาน ต้องพิมพ์คำยืนยัน สำรองและตรวจ integrity ก่อนลบ หากข้อมูลเปลี่ยนหรือมีงานพิมพ์/การนำเข้าจะไม่ล้าง
- ล้างเฉพาะตารางลูกค้า เก็บผู้ส่ง ตั้งค่า และประวัติ snapshot เดิม พร้อม reset cache และตัวอย่างใน UI
- แก้ backup พาธ Windows ใช้ online SQLite backup และ SQL gzip โดยไม่ต้องใช้ sqlite3 CLI กู้คืนได้ทั้ง .db และ .sql.gz พร้อมสำรองของเดิมก่อนแทนที่
- รายการลูกค้าไม่ถูกตัดที่ 200 ราย สถิติคิวนับทุกงานและวัน Asia/Bangkok แสดง “เข้าคิวแล้ว” และ “ส่งงานพิมพ์แล้ว” ตามสถานะที่ตรวจได้
- อัปเดตเตรียมโค้ดและ dependency ในพื้นที่แยกก่อนหยุดบริการ เปลี่ยนชุดที่ตรวจแล้วและเริ่มระบบใหม่ ไม่ฝืนทับโปรเจคที่มีงานแก้ไขค้าง
- หน้า ตั้งค่า อ่านชื่อเครื่องพิมพ์จาก Windows และตรวจชื่อ/สถานะ offline ก่อนส่งพิมพ์
- ปรับ README, กฎ AGENTS.md และ CI เป็น Windows/Ubuntu ด้วย Node.js 24

## ผลตรวจในเครื่อง

- ชุด smoke ทดสอบ API และ UI จริงกับ SQLite ชั่วคราว รวมลูกค้า 302 ราย: ยกเลิก, คำยืนยันผิด, ล้างครบ, ข้อมูลเปลี่ยน, มีงานค้าง และสำรองล้มเหลว
- ตรวจการสำรองก่อนล้างมีลูกค้าครบ กู้คืน SQL gzip และกู้คืน DB สำรองก่อนล้างโดยไม่ใช้ sqlite3 CLI
- จำลองส่งพิมพ์ล้มเหลว 100 งานแล้วไม่มีไฟล์ PDF สะสม; ตรวจไฟล์ยังอยู่ระหว่างส่ง และถูกลบหลังจบ
- สร้าง PDF และ render เป็นภาพ ตรวจสระ/วรรณยุกต์กับข้อความ มีเอกสารค่ะ ขอบคุณค่ะ ผู้ส่ง ผู้รับ น้ำ กุ้ง ปู่ ญู่ ที่อยู่ ทั้งตัวปกติและตัวหนา
- Windows cold setup ใช้สำเนาโปรเจคในพาธชื่อภาษาไทยและช่องว่าง บังคับใช้ portable Node ตรวจเตรียมระบบ เปิดซ้ำ อัปเดตจาก repo จำลอง เริ่มใหม่ และปิดระบบ
- ตรวจคำเตือนล้างข้อมูลจากภาพ UI และตรวจ syntax/ช่องว่างของไฟล์ที่แก้
- CI ถูกปรับแล้ว แต่ยังไม่ได้ยืนยันผลรันบน GitHub

ผลล่าสุด: smoke ผ่าน 30 กลุ่ม และ Windows cold setup ผ่านการเตรียมระบบ เปิดซ้ำ อัปเดต เริ่มใหม่ และปิดระบบ ทั้งหมดใช้ข้อมูลจำลองและไม่ส่งเครื่องพิมพ์จริง

## สิ่งที่ตรวจพบเพิ่มเติมบนเครื่องร้าน

Windows ติดตั้งเครื่องพิมพ์ชื่อ TP518G บน USB003 และไม่ได้ตั้ง WorkOffline ขณะที่ค่าเดิมในระบบคือ TP518 ซึ่งไม่ตรงกัน เป็นสาเหตุที่อธิบายการส่งพิมพ์งาน #10 ล้มเหลวได้ นอกเหนือจากปัญหาภาษาไทยใน PDF

เปิดระบบรุ่นใหม่ผ่านตัวเปิดแล้ว ตรวจ health พบ server/worker พร้อมในโหมด windows และปรับ printer_name เป็น TP518G ผ่าน API ตั้งค่า ข้อมูลลูกค้ายังครบ 302 ราย รวมใช้งาน 300 ราย ไม่ได้ล้างข้อมูลหรือส่งฉลากจริง

สร้างไฟล์ตัวอย่างงาน #10 ใหม่ไว้ที่ output/pdf/job-00010-corrected.pdf เพื่อเทียบต้นฉบับ โดยอ่านข้อมูลแบบ readonly และไม่ได้สั่งพิมพ์ เก็บไฟล์นี้นอก repo โค้ด

## ข้อจำกัดที่ยังต้องตรวจจริง

เพิ่มดาวลูกค้าแบบบันทึกใน SQLite และ migration ค่าเริ่มต้น 0 โดยรักษาลูกค้าเดิม รายการใช้บ่อยอยู่เหนือช่องค้นหา ดับเบิลคลิกเปิดตัวเลือกพิมพ์โดยไม่ส่งงานจนกดยืนยัน ฉลากใช้ชื่อผู้รับคอลัมน์ B เท่านั้น ไม่ใช้ชื่อย่อ A ทั้ง preview และ PDF

สร้าง icon PNG 192/512 และ ICO จาก logo.png โดยรักษาสัดส่วน เพิ่ม manifest id/scope และปุ่มติดตั้งเมื่อ Chrome ส่ง beforeinstallprompt ทางลัด Windows เรียกตัวเปิดซ่อนและใช้ ICO เดียวกัน ส่วน Startup เรียก /startup เพื่อเริ่มบริการโดยไม่เปิด browser/dialog การลงทะเบียนเป็นของผู้ใช้ปัจจุบัน ไม่ต้องสิทธิ์ administrator และทำซ้ำได้ หน้า ตั้งค่า มีปุ่มติดตั้งทางลัด

- ยังไม่ได้ส่งฉลากลงกระดาษ TP518G ต้องลองจริง 1 ใบและตรวจขนาด ความเข้ม ตำแหน่ง และจำนวน
- ตรวจภาพ PDF ไม่ใช่หลักฐานว่ากระดาษออกจริง; สถานะส่งงานพิมพ์จบเป็นผลจากโปรแกรมส่งพิมพ์
- Cold setup ต้องใช้อินเทอร์เน็ต หลังเตรียมแล้วงานประจำวันใช้ offline ได้
- การล้างลูกค้าไม่ได้ลบข้อมูลจากประวัติงานพิมพ์หรือไฟล์สำรอง ซึ่งระบุใน dialog
- GitHub connector ของเซสชันนี้เข้าถึง repo ไม่ได้ จึงใช้ Git บนเครื่องสำหรับ branch codex/windows-launcher-thai-print การรวมเข้ากับ main ยังไม่ได้ดำเนินการ
