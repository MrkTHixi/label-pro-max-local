# ตรวจระบบและแผนปรับปรุง LabelPro Local

วันที่ตรวจ: 6 ตุลาคม 2026 (Asia/Bangkok)

สถานะ: ผู้ใช้อนุมัติให้ดำเนินการแล้ว รายงานข้อค้นพบด้านล่างเป็นสภาพก่อนแก้ ดูผลดำเนินงานล่าสุดใน IMPLEMENTATION.md ข้อมูลจริงไม่ถูกใช้ในการทดสอบ และยังต้องตรวจฉลากบน TP518 จริง

| ข้อมูลเก่า | migration บางกรณีเปลี่ยนชื่อ DB เก่าแล้วสร้าง DB ใหม่ | ต้องเปลี่ยนเป็น migration รักษาข้อมูลจริง |
| สถานะ UI | popup สำเร็จเกิดเมื่อเข้าคิว; done เกิดเมื่อคำสั่งส่งพิมพ์จบ ไม่ได้ตรวจว่ากระดาษออกจริง | ควรใช้ข้อความ เข้าคิวแล้ว / ส่งไปเครื่องพิมพ์แล้ว ตามหลักฐาน |
| ยอดคิว | สถิตินับจาก 50 งานล่าสุด และวันใช้ UTC | ยอดรอ/สำเร็จวันนี้อาจไม่ครบและไม่ตรงวันไทย |

ข้อจำกัดการตรวจ: ยังไม่ได้ตรวจการกู้คืนจริง เปิดแอปบนเครื่องใหม่ หรือพิมพ์ลงกระดาษ TP518; ไม่รัน smoke เดิมเพราะมีขั้นตอนแตะฐานข้อมูลจริงผ่าน backup --dry-run

## 3. แนวทางที่เสนอ

### เปิดจากทางลัดเดียวโดยไม่มี terminal
สร้างตัวเปิดแบบไม่มี console สำหรับ Windows พร้อมตัวควบคุม server/worker: ตรวจ Node และ dependency, ติดตั้งด้วย lockfile ครั้งแรก, ตรวจบริการของโปรเจคนี้, เริ่มแบบซ่อนหน้าต่าง, รอ readiness แล้วเปิด browser ที่ localhost หากเปิดซ้ำให้ใช้ชุดเดิม ตรวจพอร์ตชนโดยไม่ฆ่าโปรแกรมอื่น และมีปุ่มหยุด/เริ่มใหม่หรือเครื่องมือจัดการที่เข้าถึงง่าย

เป้าหมายการใช้งาน: clone → เปิดทางลัด LabelPro → ครั้งแรกแสดงสถานะเตรียมระบบ → หน้าเว็บพร้อมพิมพ์; ครั้งต่อไปคลิกเดียว การติดตั้งครั้งแรกยังต้องมี runtime และอินเทอร์เน็ตสำหรับ dependency หากต้องการเครื่องที่ไม่มี Node ด้วย ให้ทำแพ็กเกจแจกจ่ายรวม runtime ในขั้นต่อยอด

HTTP shortcut อย่างเดียวไม่เริ่ม server ได้ หากต้องการเปิด URL ได้ทันทีหลังเปิดเครื่อง ใช้การตั้งเริ่มอัตโนมัติตอนเข้าสู่ Windows เป็นตัวเลือกหลังติดตั้ง ไม่เพิ่มภาระตั้ง service ให้ผู้ใช้งานทั่วไปเป็นขั้นตอนหลัก

อ้างอิงการซ่อน process: https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1

### แก้ฉลากไทย
เสนอใช้ HTML/CSS renderer ผ่าน Chromium ที่รองรับการวางอักษรไทย โดยใช้เทมเพลตเดียวสำหรับ preview และ PDF กำหนด @page 100mm 150mm, ฝัง/จัดส่งฟอนต์ไทยที่มีสิทธิแจกจ่าย, รอโหลดฟอนต์ก่อนสร้าง PDF และทำงาน offline หลังเตรียมระบบครั้งแรก

เริ่มด้วยต้นแบบเฉพาะ renderer ใช้ข้อมูลสมมติที่มี ผู้ส่ง ผู้รับ มีเอกสารค่ะ ขอบคุณค่ะ น้ำ ที่อยู่ และเครื่องหมายซ้อน ตรวจภาพและขนาดหน้าให้ผ่านก่อนเปลี่ยนเส้นทางพิมพ์จริง เพิ่มการวัดพื้นที่และย่ออย่างมีขอบเขตหรือแจ้งว่าข้อความยาวเกิน ห้ามปล่อยทับท้ายฉลาก

แนวทางนี้เพิ่ม dependency ของ browser จึงต้องรวมการติดตั้งในตัวเปิดครั้งแรก และใช้ renderer ร่วมใน worker เพื่อลดการเปิด browser ต่อฉลาก รายละเอียด page.pdf และ preferCSSPageSize: https://playwright.dev/docs/api/class-page#page-pdf

### ไม่ทิ้งไฟล์ฉลากทุกงาน
สร้าง PDF ในหน่วยความจำ แล้วเขียนไฟล์ชั่วคราวเฉพาะช่วงส่งให้โปรแกรมพิมพ์ ใช้โฟลเดอร์ temp เฉพาะ LabelPro และลบใน finally หลังโปรแกรมอ่านเสร็จทั้งสำเร็จและล้มเหลว เมื่อเริ่มระบบให้ล้างไฟล์เก่าที่หมดอายุโดยไม่แตะไฟล์งานที่ยังใช้งาน

ประวัติเก็บใน SQLite และ log แบบจำกัดขนาด ถ้าต้องการตรวจ PDF ให้กดดาวน์โหลดเฉพาะงานหรือเปิด debug ที่จำกัดจำนวนไฟล์ ไฟล์ใน printed/ เดิม รวมถึง PDF ตัวอย่าง จะไม่ลบในการตรวจครั้งนี้

### ปุ่มล้างลูกค้าทั้งหมด
เพิ่มปุ่มสีแดงในหน้าลูกค้า เปิด dialog แสดงจำนวนจริงจากฐานข้อมูลทั้งหมดรวมที่ปิดใช้งาน บอกว่าประวัติพิมพ์ยังมีข้อมูล snapshot ให้พิมพ์คำว่า ล้างข้อมูล เพื่อเปิดปุ่ม ยืนยันล้างลูกค้าทั้งหมด พร้อมปุ่มยกเลิก

ขอบเขตที่เสนอ: ลบถาวรเฉพาะตาราง customers รวมรายการปิดใช้งาน โดยรักษาข้อมูลผู้ส่ง ตั้งค่า และประวัติพิมพ์ สำรอง DB ในเครื่องก่อนและหยุดทันทีถ้าสำรองล้มเหลว ป้องกันเพิ่ม/นำเข้าแข่งกับการล้าง หากมีงาน queued/printing ให้แจ้งจัดการคิวก่อนล้าง จากนั้นล้างด้วย transaction และ reset ลูกค้าที่เลือก/cache/preview/search/list

ไม่ใช้ soft delete โดยติดป้ายว่าล้างถาวร หากต้องการลบข้อมูลลูกค้าจากประวัติพิมพ์หรือไฟล์สำรองด้วย ถือเป็นขอบเขตเพิ่มที่ต้องกำหนดแยก

## 4. ลำดับแผนงานและเกณฑ์รับงาน

| ขั้น | งาน | เกณฑ์ผ่าน |
| --- | --- | --- |
| 1 | แก้ backup Windows และสร้าง fixture/test ที่แยกข้อมูลจริง | สำรองในพาธไทย/มีช่องว่างได้ และทดสอบกู้คืนใน DB ชั่วคราวได้ |
| 2 | ทำต้นแบบ renderer ภาษาไทยและเทมเพลตร่วม | PDF 1 หน้า 100×150 มม., เครื่องหมายถูก, ข้อความยาวไม่ทับกัน, preview ตรง PDF |
| 3 | แก้ worker snapshot/รอบซ้อน และจัดการ temp | งานทีละงาน, ใช้ผู้ส่งตาม snapshot, กรณีสำเร็จ/ล้มเหลวไม่สะสม PDF และ cleanup หลังหยุดผิดปกติ |
| 4 | ตัวเปิด Windows และการตรวจความพร้อม | clone ใหม่เปิดจากทางลัดได้, server/worker พร้อม, ไม่มี console รบกวน, เปิดซ้ำไม่สร้าง process ซ้อน |
| 5 | เพิ่ม API/ปุ่ม/คำเตือนล้างลูกค้า | ทดสอบยกเลิกแล้วข้อมูลครบ, backup fail แล้วไม่ล้าง, ยืนยันล้างครบมากกว่า 200 ราย และ UI ไม่มีลูกค้าเก่าค้าง |
| 6 | แก้จำนวนรายการ/ยอดคิว/วันไทย/สถานะ และคู่มือ CI | จำนวนครบ, วัน Asia/Bangkok, runtime ตรงกัน, ข้อความตรงสถานะจริง |
| 7 | ตรวจเครื่อง TP518 จริง 1 ใบ แล้วจำนวนหลายใบ | กระดาษขนาดถูก ภาษาไทยถูก จำนวนถูก ไม่มีงานซ้ำ ไม่มีไฟล์สะสม |
