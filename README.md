# LabelPro Local

ระบบพิมพ์ฉลากพัสดุภาษาไทย 100 × 150 มม. สำหรับ Windows ประจำสาขา ทำงานในเครื่องเดียว ไม่ต้องใช้ cloud ในงานประจำวัน

คู่มือติดตั้งเครื่องใหม่และใช้งานตั้งแต่เริ่มต้น: [web/manual.html](web/manual.html) และ [คู่มือ PDF](web/manual.pdf) เปิดได้จากหน้า ตั้งค่า → คู่มือติดตั้งและใช้งาน / ดาวน์โหลดคู่มือ PDF

## เปิดใช้งานจากโปรเจคที่ clone มา

1. ดับเบิลคลิก **start-labelpro.vbs** ในโฟลเดอร์โปรเจค หรือสร้าง shortcut ของไฟล์นี้ไว้บน Desktop
2. ครั้งแรกตัวเปิดเตรียม Node.js, dependency และ Chromium ให้อัตโนมัติ มีหน้าต่างสถานะสั้น ๆ และต้องใช้อินเทอร์เน็ต หากไม่มี Node.js 22 ขึ้นไป จะดาวน์โหลด Node.js 24 แบบ portable จาก nodejs.org ตรวจ SHA256 และเก็บใน `.runtime/` ไม่ติดตั้งทับ Node ของเครื่อง
3. เมื่อเว็บและตัวพิมพ์พร้อม ตัวเปิดจะเปิด **http://localhost:3000** ให้เอง ไม่มี terminal ที่ต้องเปิดค้าง

ครั้งต่อไปเปิดทางลัด LabelPro Local บน Desktop ได้เลย บริการเริ่มเบื้องหลังเมื่อเข้า Windows ของผู้ใช้ที่ติดตั้งทางลัด หากปิดบริการไว้ ทางลัด Desktop จะเริ่มให้ใหม่ ลิงก์ HTTP หรือ bookmark อย่างเดียวไม่เริ่มบริการเอง

**เปิดซ้ำได้:** ใช้ระบบชุดที่กำลังทำงานอยู่ ไม่เริ่ม worker ซ้อน หากพอร์ตถูกใช้โดยแอปอื่นจะมีข้อความแจ้งและไม่ฆ่าโปรแกรมนั้น

**ปิด/เริ่มใหม่:** หน้า ตั้งค่า มีปุ่มเริ่มระบบใหม่และปิดระบบ หรือดับเบิลคลิก **stop-labelpro.vbs** งานที่เริ่มส่งพิมพ์แล้วจะทำให้จบก่อนปิด ไม่สั่งงานเดิมซ้ำเองหลังหยุดผิดปกติ

**ผู้ใช้ที่เคยเปิดแบบเดิม:** ปิด terminal ของ server และ worker เดิมก่อนเปิด start-labelpro.vbs ระบบจะแจ้งเมื่อพบ server ที่ไม่ได้เปิดผ่านตัวควบคุมใหม่

start-labelpro.bat เก็บไว้เพื่อรองรับทางลัดเดิม แต่จะส่งต่อไปตัวเปิด VBS หน้าต่างคำสั่งอาจปรากฏสั้น ๆ จึงควรใช้ VBS โดยตรง

ไฟล์ VBS ใช้ Windows Script Host หากเครื่ององค์กรปิดการใช้ Script Host ให้ผู้ดูแลสร้าง shortcut เรียก `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\path\labelpro-local\scripts\launch.ps1"` โดยไม่ต้องเปิด terminal ค้าง

## วิธีใช้งาน

- ค้นหาด้วยชื่อสถานที่ / กรุณาส่ง / ติดต่อ แล้วเลือกดูตัวอย่างฉลาก
- ดับเบิลคลิกลูกค้า หรือกดปุ่มเครื่องพิมพ์ เลือกข้อความ จำนวน 1–20 ใบ และผู้สั่งพิมพ์
- เมื่อกดสั่งพิมพ์ ระบบรับเข้าคิวทันที ตัวพิมพ์ทำงานเบื้องหลังทีละงาน
- คิวแสดง 50 งานล่าสุด แต่ยอดรอพิมพ์ ล้มเหลว และส่งพิมพ์วันนี้นับจากทุกงาน วันใช้ Asia/Bangkok
- สถานะ “ส่งงานพิมพ์แล้ว” หมายถึงโปรแกรมส่งพิมพ์จบ ไม่ใช่การตรวจยืนยันว่ากระดาษออกจริง
- ดาวน์โหลด PDF ของงานเฉพาะเมื่อจำเป็นจากปุ่ม **PDF** ในหน้าคิว ไม่มีการเก็บ PDF ทุกงานไว้ในโปรเจค

## ฉลากภาษาไทยและเครื่องพิมพ์

ผู้รับบนฉลากใช้ชื่อร้าน/ชื่อผู้รับจากคอลัมน์ B เท่านั้น ชื่อย่อคอลัมน์ A ใช้สำหรับค้นหาและไม่พิมพ์บนกระดาษ กด ☆ ข้างรายการลูกค้าเพื่อบันทึกเป็นที่อยู่ใช้บ่อย รายการติดดาวแสดงเหนือช่องค้นหาแม้ค้นหาคำอื่น ดับเบิลคลิกเปิดตัวเลือกพิมพ์ แล้วกดยืนยันก่อนส่งงาน

ตัวเปิดสร้างทางลัด **LabelPro Local** บน Desktop พร้อมโลโก้ที่ใช้ในแอป และลงทะเบียนเริ่มระบบแบบซ่อนเมื่อเข้า Windows ของผู้ใช้ปัจจุบัน ทางลัด Desktop เริ่มบริการให้ก่อนเปิดหน้าต่าง Chrome จึงเปิดได้แม้ปิดบริการไว้ หน้า ตั้งค่า มีปุ่มสร้างทางลัดใหม่หากย้ายโปรเจค สำหรับแอปที่ติดตั้งจากเมนู Chrome ใช้ไอคอนโลโก้จาก manifest; หากติดตั้งก่อนเปลี่ยนโลโก้และยังแสดงไอคอนเดิมให้ติดตั้งแอปใหม่ การเปิดจากทางลัด Chrome ใช้บริการที่เริ่มเมื่อเข้า Windows ถ้าปิดบริการเองให้ใช้ทางลัด LabelPro Local เพื่อเริ่มใหม่

ตัวอย่างหน้าเว็บและ PDF ใช้ `web/label-template.js` และ `web/label.css` ชุดเดียวกัน สร้าง PDF ด้วย Chromium ซึ่งจัดวางสระและวรรณยุกต์ไทย ใช้ Noto Sans Thai ที่เก็บใน `web/fonts/` พร้อมใบอนุญาต OFL ไม่โหลดฟอนต์จากอินเทอร์เน็ตขณะพิมพ์

PDF มีหน้าเดียว ขนาด 100 × 150 มม. ตัวเรนเดอร์ปรับขนาดตัวอักษรเนื้อหาในขอบเขตจำกัด หากข้อความยังยาวเกินพื้นที่จะขึ้นข้อผิดพลาด ไม่ตัดข้อมูลทิ้งหรือทับท้ายฉลาก

บน Windows ใช้ SumatraPDF ที่มากับ `pdf-to-printer` ส่งเข้า spooler แบบซ่อนหน้าต่างและขนาดจริง `noscale`:

1. ติดตั้ง Windows driver ของ TP518 และเชื่อมต่อเครื่องพิมพ์
2. ตั้งกระดาษใน Printing preferences เป็น **100 × 150 mm**
3. เลือกชื่อเครื่องพิมพ์จากรายการในหน้า ตั้งค่า ให้ตรงกับชื่อใน Windows (หรือกำหนด PRINTER_NAME) ระบบตรวจชื่อและสถานะ offline ก่อนส่งพิมพ์
4. ทดลองฉลากจริง 1 ใบ ตรวจภาษาไทย ขนาด ความเข้ม และจำนวน ก่อนใช้ชุดใหญ่

ไฟล์ PDF ชั่วคราวอยู่ใน `%TEMP%/labelpro-print-<รหัสโปรเจค>/job-<id>-<รหัสสุ่ม>/` และลบหลังโปรแกรมส่งพิมพ์จบทั้งสำเร็จและล้มเหลว ไฟล์จาก process ที่หยุดผิดปกติจะถูกล้างเมื่อเก่ากว่า 24 ชั่วโมงขณะเริ่ม worker ไฟล์ตัวอย่างเก่าใน `printed/` ไม่ถูกลบโดยการอัปเดตนี้

โหมดทดลองใช้ `PRINT_DRIVER=mock` ไม่ส่งเครื่องพิมพ์จริงและไม่สร้าง TXT ทุกงาน หน้า ตั้งค่า แจ้งว่ากำลังใช้โหมดทดลอง บน Windows ค่าเริ่มต้นเป็น windows; ระบบอื่นเป็น mock

## ลูกค้าและล้างข้อมูล

ข้อมูลลูกค้า 4 ช่อง: ชื่อสถานที่ / กรุณาส่ง / ที่อยู่ / ติดต่อ นำเข้า Excel ผ่านหน้าลูกค้า โดยใช้ชีต **PrintLabel** แถวหัวตารางและชื่อสถานที่ว่างจะถูกข้าม ไฟล์ต้นฉบับไม่ถูกแก้ไข การนำเข้าปัจจุบันเพิ่มรายการ ไม่ตรวจรายการซ้ำอัตโนมัติ

ลบรายคนเป็น **ปิดใช้งาน** ข้อมูลยังอยู่ในฐานข้อมูล

ปุ่ม **ล้างข้อมูลลูกค้าทั้งหมด** เป็นการลบถาวรจากตารางลูกค้า รวมรายการที่ปิดใช้งานแล้ว:

- dialog แสดงจำนวนจริงทั้งหมดและผลกระทบ ให้พิมพ์ “ล้างข้อมูล” ก่อนยืนยัน
- ต้องจัดการคิวที่รอ/กำลังพิมพ์และรอนำเข้าให้จบก่อน
- ระบบสร้างและตรวจไฟล์สำรอง `.db` ก่อนลบ หากสำรองไม่ได้จะไม่ล้าง
- ข้อมูลเปลี่ยนหลังเปิดคำเตือนต้องเปิดคำเตือนเพื่อตรวจจำนวนใหม่
- ข้อมูลผู้ส่ง ตั้งค่า ประวัติพิมพ์ และไฟล์สำรองยังคงอยู่ **ประวัติพิมพ์ยังมีชื่อ ที่อยู่ และข้อมูลติดต่อแบบ snapshot**

ไม่มีการล้างลูกค้าอัตโนมัติจากการเปิดหรืออัปเดตแอป

## สำรองและกู้คืน

สำรองอัตโนมัติเมื่อเพิ่มลูกค้ารายคน หรือกด **สำรองข้อมูลตอนนี้** ไม่มีสำรองตามเวลา ก่อนล้างลูกค้าสำรองเพิ่มเฉพาะขั้นตอนล้างนั้น

- ใช้ SQLite online backup และตรวจ integrity จึงไม่ต้องมี sqlite3 CLI
- สำรองทั่วไปเก็บ `.db` และ SQL gzip ที่ `backups/` แล้ว commit SQL gzip ลง repo แยก `data-backup/`
- ถ้ากำหนด backup_repo_url จะ push ไป repo ที่กำหนด เมื่อ Git/เน็ตไม่พร้อม ยังมีสำรองในเครื่องและแจ้งส่วนที่ยังไม่สำเร็จ
- เก็บไฟล์สำรองทั่วไปล่าสุด 60 ไฟล์ (ประมาณ 30 ชุด) ส่วนสำรองก่อนล้างและก่อนกู้คืนไม่ถูก prune อัตโนมัติ
- `.sql.gz` เป็น SQL บีบอัด ไม่ใช่ไฟล์ที่ git diff อ่าน SQL ได้โดยตรง
- ข้อมูลลูกค้าและสำรองถูกกันออกจาก repo โค้ดด้วย .gitignore

กู้คืนได้ทั้ง `.db` และ `.sql.gz` หลังปิดระบบด้วย stop-labelpro.vbs:

```powershell
npm run restore -- "C:\path\labelpro-before-clear-....db"
```

ตัวกู้คืนตรวจฐานข้อมูลที่นำเข้า สำรองฐานข้อมูลปัจจุบันก่อนแทนที่ และไม่ต้องใช้ sqlite3 CLI ถ้าใช้ portable Node ให้เรียก node.exe ใน `.runtime/` กับ `scripts/restore.mjs` หรือให้ผู้ดูแลช่วยกู้คืน

## อัปเดตจาก GitHub

ปุ่มอัปเดตตรวจโปรเจคว่ามีไฟล์แก้ไขค้างหรือไม่ และต้องจัดการคิวให้จบก่อน เตรียม checkout, dependency และ Chromium ใน `.runtime/update-.../` แยกจากระบบที่รันอยู่ เมื่อตรวจพร้อมแล้วจึงหยุดบริการ เปลี่ยน dependency และ fast-forward โค้ด แล้วเริ่มระบบใหม่ หากเตรียมไม่สำเร็จ ระบบเดิมยังทำงาน

ดูผลในหน้า ตั้งค่า และ `data/runtime.log` โฟลเดอร์เตรียมอัปเดตเก็บไว้เพื่อกู้กลับ ไม่อัปเดตโปรเจคที่มีงานแก้ไขค้างหรือ branch diverge โดยฝืนทับงาน

## โครงสร้าง

```text
start-labelpro.vbs → scripts/launch.ps1 → scripts/runtime.mjs
                                         ├─ server/index.mjs → web/ + API
                                         └─ server/print-worker.mjs
Browser → Express → data/labelpro.db → queue → Chromium PDF → Windows spooler
```

รายละเอียดทุกไฟล์และข้อค้นพบเดิมอยู่ใน [docs/PROJECT-PLAN.md](docs/PROJECT-PLAN.md) กฎการพัฒนาอยู่ใน [AGENTS.md](AGENTS.md) และผลทดสอบล่าสุดอยู่ใน [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md)

ตารางหลัก: customers, sender_profile, print_jobs, settings, backup_log, worker_state ข้อมูลแยกแต่ละสาขา ไม่มีการซิงค์

## สำหรับผู้พัฒนา

Node.js 22 ขึ้นไป; CI ใช้ Node.js 24 ทั้ง Windows และ Ubuntu:

```powershell
npm ci
npm run setup
npm start
npm run smoke
npm run test:windows
```

npm start เปิดตัวควบคุมรวม; npm run server / npm run worker เปิดแยกสำหรับ debug ชุด smoke ใช้ฐานข้อมูลชั่วคราวและเครื่องพิมพ์จำลอง ทดสอบ API จริง การกด UI สำรอง กู้คืน ไฟล์พิมพ์ และ migration; test:windows คัดลอกโปรเจคใหม่ในพาธภาษาไทย/ช่องว่างและตรวจตัวเปิดแบบ cold setup

ตัวแปร: PORT (3000), LABELPRO_DB, LABELPRO_DATA_DIR, LABELPRO_BACKUPS_DIR, LABELPRO_BACKUP_REPO, LABELPRO_PRINT_TEMP, PRINT_DRIVER, PRINTER_NAME รองรับแยกพื้นที่ทดสอบทั้งหมด Log จำกัดขนาดประมาณ 2 MB ต่อไฟล์และเก็บรุ่นก่อนหน้า 1 ไฟล์

ผลตรวจ PDF ไม่แทนการตรวจฉลากบนกระดาษจริง ต้องยืนยันกับ TP518 ของร้านอีกครั้ง
